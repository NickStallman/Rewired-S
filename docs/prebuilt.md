# Pre-built images

A pre-built image is a Rewired-S firmware you install without compiling anything. It is the same
production package set as the compiled entries, with everything a site file or `secrets.yaml`
would hold provisioned at runtime instead and stored on the dongle:

| What | Compiled build | Pre-built image |
|---|---|---|
| Wi-Fi | `secrets.yaml` | captive portal (and Improv over the UART console on the WiNet-S) |
| Web login | `secrets.yaml` | default `admin` / `rewired-s`, changed on the Settings page |
| Native API key | `secrets.yaml` | generated by Home Assistant when it adopts the dongle |
| MQTT broker | `secrets.yaml` | Settings page |
| Cloud version | `cloud_firmware_version` substitution | read from the stock app in the other flash slot |
| Updates | `make deploy` / native OTA | the **Firmware** update entity (release manifest) |

There are four images, one per entry: `winet-s-prebuilt.yaml` (Wi-Fi), `winet-s-ethernet-prebuilt.yaml`,
`winet-s2-prebuilt.yaml` (Wi-Fi) and `winet-s2-ethernet-prebuilt.yaml`. The entries share one
node name, `rewired-s`, and append the last three bytes of the MAC address (`rewired-s-a1b2c3`), so
several dongles can live on one network. They are built by `common/provisioning.yaml`,
`common/wifi_provisioned.yaml`, `common/improv_serial.yaml` and `common/mqtt_ha_provisioned.yaml`;
`tests/test_prebuilt_no_secrets.py` proves that no `!secret` is reachable from them, and
`make config-prebuilt` validates them with `secrets.yaml` moved out of the way. Installing the
image follows [install_ota.md](install_ota.md) (through the stock updater) or
[install_serial.md](install_serial.md) (over the UART pads).

## First boot: the access point

A Wi-Fi image with no network stored starts its own access point:

- name `rewired-s-xxxxxx` (the node name with the MAC suffix), password `rewired-s-setup`;
- join it and open `http://192.168.4.1`: the captive portal lists the networks it sees, takes the
  name and password of yours and stores them in the dongle's NVS. The dongle then joins that
  network and the access point goes away (it comes back whenever the network cannot be reached,
  unless the button's two-click turns the fallback AP off; `common/board_io.yaml`).

The password of the access point is the `ap_password` substitution of `common/wifi_provisioned.yaml`;
a site file that includes a prebuilt entry can change it (`tests/config/prebuilt-site-example.yaml`).

On the WiNet-S Wi-Fi image the same credentials can be given over the UART console pads with
[Improv Serial](https://www.improv-wifi.com/serial/): the ESPHome dashboard and the ESP Web Tools
install page offer it right after a serial flash.

Ethernet images need no provisioning: they come up on DHCP.

## Finding the dongle and logging in

The web UI answers at `http://rewired-s-xxxxxx.local/` (mDNS) or at the address your router
shows. The login is HTTP digest with the username `admin` and the password `rewired-s` until you
change it: **Settings → Web login** asks for the current password, the new username and the new
password twice (8–63 printable characters without `:`). The pair is stored in NVS and survives
updates; while the defaults are in use the Settings page shows a warning banner. The same password
guards the native OTA port (below).

## Home Assistant

### The dongle itself (native API)

Home Assistant discovers `Rewired-S` through the ESPHome integration. The image is built with API
encryption but no key: at adoption Home Assistant generates a key, stores it on the dongle and
uses it from then on (expected; not yet confirmed on hardware). Until then the native API is
plaintext on the LAN, so adopt the dongle soon after installing it. A device adopted this way
keeps its key across updates; the 30 s reset (below) drops it, after which Home Assistant adopts
it again.

Adopting it in the ESPHome dashboard writes a configuration that fetches the pre-built entry from
GitHub as a remote package, pinned to the release the dongle runs
([ESPHome](esphome.md#your-configuration)).

### The inverter, batteries and meter (MQTT)

Each device on the RS485 bus becomes its own Home Assistant device through MQTT discovery
([home_assistant.md](home_assistant.md)). The broker is set on **Settings → Home Assistant**:
host, port, username, password (write-only: it is never shown again, a blank field keeps it, the
*clear* box drops it), discovery prefix and TLS. Saving stores the record in NVS, restarts the
MQTT client against the new broker and re-publishes every device's discovery; the status pill
shows *connected*, or the last error (`connection refused: bad username or password`, `transport
error: ...`). An empty host turns MQTT off. The `MQTT connected` binary sensor reports the same
state to Home Assistant.

A compiled build that names the broker in its configuration shows the form read-only.

### Updates

The **Firmware** update entity (`update.rewired_s_xxxxxx_firmware`) checks the release manifest
at `https://nickstallman.github.io/Rewired-S/firmware/<entry>/manifest.json` every six hours and
installs the next release over HTTPS when you press *Install*. This path works before the dongle
is adopted, needs no key or password, and is the normal way to update a pre-built image. The
native OTA port (3232) is also open: it asks for the web login password until the dongle is
adopted and accepts the API key as well after that (`esphome upload --password`, or a
[configuration](esphome.md#your-configuration) with `ota: password:` set to your web password).

## The version reported to iSolarCloud

The dongle tells iSolarCloud a dongle firmware version ([cloud_identity.md](cloud_identity.md)).
A pre-built image cannot know the version your dongle shipped with, so it reads it from the stock
app the updater left in the other OTA slot, the first time it boots, and keeps it in NVS (the next
update overwrites that slot). **Settings → iSolarCloud identity** shows the reported version and
where it came from (*read from the stock image*, *the built-in default*, *set here*), offers
*Use detected* / *Use default*, and takes an override typed from the stock web UI's About page. An
override applies at once, without a restart.

## Back to stock

**Settings → Boot slots** shows which slot the dongle runs from and what the other slot holds.
*Boot other slot* (after a confirm dialog) rewrites the boot record so the other slot starts next
and restarts the dongle; nothing else on the flash changes. Home Assistant has the same as the
`Allow boot switch` switch (off after every boot; it arms one press) and the `Boot other slot`
button. [back_to_stock.md](back_to_stock.md) has the whole picture.

## Resetting everything

Hold the button for 30 s and release it: the dongle erases ESPHome's NVS namespace (Wi-Fi
credentials, the web login, the MQTT settings, the API key, the cloud-version record, restored
switch states) and restarts into the access point. The external flash with the stock identity and
the other app slot are never touched (`common/board_io.yaml`).

## Usage reporting

Pre-built images report anonymous usage like every other build ([analytics.md](analytics.md)).
The **Usage reporting** switch (Settings → Diagnostics, and Home Assistant) turns it off and is
remembered across restarts; *Send diagnostics* keeps working either way.

## What to know before installing one

- **Captive-portal upload.** While the access point is up, the captive portal's firmware upload
  page is reachable without a login (ESPHome design: it is the recovery path). The access point's
  password is the only guard, so change `ap_password` in a site file if the default is not
  acceptable, and provision the dongle promptly so the access point goes away.
- **Plaintext API until adoption.** The native API carries no encryption until Home Assistant
  sets the key. Adopt the dongle soon after installing it.
- **Default web login.** `admin` / `rewired-s` is public. The Settings page shows a banner until
  you change it; the native OTA port shares that password.
- **MQTT password in NVS.** The broker password is stored in the dongle's NVS in the clear (these
  dongles have no flash encryption). Use a broker account that can only do what the dongle needs.
- **Rollback and the network fallback.** WiNet-S: no rollback, recover over UART
  ([install_serial.md](install_serial.md)). WiNet-S2: rollback expected, unconfirmed; use **Boot
  other slot**. The Ethernet images' network fallback (`common/ethernet_fallback.yaml`; not yet
  seen firing on hardware) boots the other slot when a new build never gets a network. The
  fallback only boots a non-Ethernet Rewired-S image; with the stock app in the other slot it
  stays idle. Details: [limitations.md](limitations.md#hardware).
- **A second update overwrites the stock app.** The other slot holds the stock app only until the
  next update lands in it. The detected cloud version is kept from the first boot. The way back to
  stock after that: the extracted stock app over ESPHome OTA (unverified) or, on the WiNet-S,
  serial ([back_to_stock.md](back_to_stock.md)).
